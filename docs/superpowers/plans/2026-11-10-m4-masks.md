# M4 Masks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mask variants for window and corridor orienteering. A mask hides the map outside its windows, is assigned to courses, and is drawn white above the map and below the course overprint. White-out objects from a Purple Pen file become mask variants. `check` warns about overprint that the mask leaves without map.

**Architecture:** A mask is a set of polygons in map coordinates (outline plus holes). The masked region is the outline minus its holes, so a hole is a window onto the map. The mask is stored in the project file (`[[masks]]`), assigned per course (`[[assignments]] mask = …`), turned into white fill shapes in page millimetres by the course sheet, and painted by the PDF writer after all map primitives and before the overprint layers. Because the overprint is drawn with Multiply, the lower purple painted after the mask looks the same as under black (ADR 0034). Generators for the two common shapes (a window around a leg range, a corridor along a polyline) append masks to the project file the way `numbers accept` appends corrections.

**Tech Stack:** Rust 2024, the existing renderer and PDF writer, `freemapper-course` (core v0.3.0) for the course model; no new dependencies. Polygon work is small and local (point-in-polygon, ring orientation, offset of a polyline), written without a geometry crate.

**Spec:** `docs/superpowers/specs/2026-11-08-freemapper-print-design.md` (§4 mask variant and sheet, §5.3 white-out, §5.5 project file, §5.7 overprint above masks, §7 M4 and its examples). ADRs 0025 (project file), 0034 (overprint layers), 0035 (course sheets), 0038 (number placement), 0044 (base area).

## Global Constraints

- Mask coordinates are map coordinates in millimetres at map scale, y as OOM shows it (up), the same convention as `centre_map_mm` (ADR 0028 and the manual, ch. 6). The loader converts to the internal frame once.
- A mask variant holds one or more polygons; each polygon is an outline ring plus hole rings. The masked region is the outline minus the holes (even-odd). Holes of one polygon must lie inside its outline and must not overlap each other; polygons of one variant must not overlap. The loader refuses anything else with file:line (an overlapping hole would be painted by the even-odd rule and show map where the user expects white).
- The mask is white (`DirectColour::WHITE`), painted after all map primitives and before both overprint layers, clipped to the map frame. It never hides the course overprint, the sheet elements, the frame line or the footer. The base area (ADR 0044) is covered by the mask like any other object.
- A course has zero or one mask. An assignment names a course (by name) and optionally a mask id; a sheet without a mask prints as before, byte for byte.
- White-out objects from a `.ppen` become mask variants named `whiteout-<n>` ("white-out is read but waits for M4", ADR 0033): the reader already yields `Special::WhiteOut` with its rings and a course filter. They apply to the courses of their filter; an explicit `mask` in an assignment wins over a white-out.
- Exact scale and the credit line are untouched. All M1 to M3 example PDFs stay byte-identical (`cmp`); masks add output only where an assignment names one.
- Hostile input is bounded (ADR 0019): at most 64 mask variants, 256 polygons per variant, 4096 points per ring and 100 000 points per project; a ring has at least 3 distinct points and finite coordinates.
- Program texts in DE and EN through Fluent, passed through unslop and humanizer; German uses „…“; „Bundesland“ for German states. Every significant decision gets an ADR; every user-visible change both changelogs; new terms the glossary.
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass after every task, on three OSes. Query crates.io only with the User-Agent `freemapper-print-dev`; never put an e-mail address in a header or URL.

## Review Focus

1. **A mask that hides what the runner needs.** The user expects the course overprint, numbers and the description box always visible, and `check` to warn when a marked route, crossing point or forbidden route (upper purple) or a control lies where the mask removes the map. Pinned in Task 3: `check_warns_for_overprint_in_masked_area`, `check_warns_for_control_in_masked_area`.
2. **Holes that overlap or leave the outline.** A hand-written mask with overlapping windows or a hole outside the outline must not silently print wrong. Pinned in Task 1: `overlapping_holes_refused`, `hole_outside_outline_refused`.
3. **Ring orientation and self-intersection.** A ring written clockwise or counter-clockwise must print the same; a self-intersecting ring is refused with file:line. Pinned in Task 1: `ring_orientation_does_not_matter`, `self_intersecting_ring_refused`.
4. **A course whose mask id no longer exists**, or a mask that no course uses. The user expects `check` to name both and the other courses to export. Pinned in Task 1: `unknown_mask_in_assignment_refused`, `unused_mask_is_noted`.
5. **The mask next to the base area and the page edge.** The base area is covered, nothing paints outside the frame, and a window at the map edge prints correctly. Pinned in Task 2: `mask_covers_the_base_area`, `window_at_the_frame_edge_is_clipped`.

### Task 1: Masks in the project file

**Files:**
- Modify: `crates/freemapper-print/src/project.rs` (new `Mask`, `MaskPolygon`, `Assignment.mask`, validation, `append_mask`), `crates/freemapper-print/src/courses.rs` (white-out → mask variants, stale reports), `docs/adr/` (new ADR), `docs/glossary.md`
- Create: `crates/freemapper-print/src/mask.rs` (geometry: orientation, point in polygon, ring checks), tests in the same files

**Interfaces:**
- Produces:
  - `pub struct Mask { pub id: String, pub polygons: Vec<MaskPolygon> }` and `pub struct MaskPolygon { pub outline: Vec<[f64; 2]>, pub holes: Vec<Vec<[f64; 2]>> }`, serialised as in spec §5.5 (`[[masks]]`, `polygons = [[[[x, y], …], [[x, y], …]]]`, first ring the outline). Mask ids are plain names like layout ids (file-name-safe is not required).
  - `Project.masks: Vec<Mask>` (skipped on save when empty) and `Assignment.mask: Option<String>`.
  - `mask::masked_rings(&Mask) -> Vec<Vec<Pt>>` (all rings in the internal frame, outline first, for even-odd filling) and `mask::contains(&Mask, point) -> bool` (inside the masked region).
  - `courses::mask_for(project, loaded, course) -> Option<MaskRef>` where `MaskRef` is `Project(&Mask)` or `WhiteOut(Mask)`, with the rule: assignment mask, else the white-out of the course, else none.
  - New `Stale::Mask { course, mask }` for an assignment naming a mask that does not exist (an error at load: refused with file:line) and a note `MaskUnused { id }` (info) for masks no assignment uses and no white-out replaces.
- Consumes: `LoadedProject`, `LoadedCourses`, `Special::WhiteOut` from `freemapper-course`.

- [ ] **Step 1: Failing tests** in `project.rs` and `mask.rs`: `mask_round_trips_in_the_project_file` (the committed examples re-save byte-identically; a project with a mask re-saves without change), `unknown_mask_in_assignment_refused` (file:line), `overlapping_holes_refused`, `hole_outside_outline_refused`, `overlapping_polygons_refused`, `self_intersecting_ring_refused`, `ring_orientation_does_not_matter` (`masked_rings` normalises the orientation; `contains` agrees for both), `limits_enforced` (one case just over each limit), `non_finite_point_refused`, `contains_respects_holes` (point in a hole is not masked, point in the outline outside holes is), `unused_mask_is_noted`.
- [ ] **Step 2: Implement** the types, the validation with file:line (use the loader's existing `with_line`/`field_offset` machinery), the mask geometry (segment intersection tests; O(n²) per ring with the point limits above is fine), the coordinate conversion from OOM-displayed (y up) to the internal frame, and the white-out to mask conversion in `courses.rs`.
- [ ] **Step 3: Verify** `cargo test --workspace`, then re-export the four examples and `cmp` against the committed PDFs.
- [ ] **Step 4: ADR "Mask variants"** (project file shape, coordinate convention, the even-odd definition and the disjointness rule with its reason, limits, white-out rule). Glossary rows: mask variant, window, corridor, masked area. Commit `feat(project): mask variants and their assignment`.

### Task 4: Generators and the CLI

- Modify: `crates/freemapper-print-cli/src/main.rs` (`masks window`, `masks corridor`), ftl files, `crates/freemapper-print/src/project.rs` (`append_mask`)

**Interfaces:**
- Produces:
  - `mask_build::corridor(path: &[[f64; 2]], half_width_mm: f64) -> Option<MaskPolygon>`: the corridor along a polyline as a hole in a rectangle outline covering the map extent plus margin; refuses a self-intersecting result (returns `None` with a reason through a `Result`).
