# M4 Masks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mask variants for window and corridor orienteering. A mask hides the map outside its windows, is assigned to courses, and is drawn as a clip on the map, below the course overprint. White-out objects from a Purple Pen file become mask variants. `check` warns about overprint that the mask leaves without map.

**Architecture:** A mask is a set of polygons in map coordinates (outline plus holes). The masked region is the outline minus its holes, so a hole is a window onto the map. The mask is stored in the project file (`[[masks]]`), assigned per course (`[[assignments]] mask = …`), turned into clip rings in page millimetres by the course sheet, and applied by the PDF writer to all map primitives. Because the mask clips the map and the overprint is drawn on top, nothing else changes in the paint order. Generators append masks to the project file the way `numbers accept` appends corrections.

**Tech Stack:** Rust 2024, the existing renderer and PDF writer, `freemapper-course` (core v0.3.0) for the course model; no new dependencies. Polygon work is small and local (point-in-polygon, ring orientation, offset of a polyline), written without a geometry crate.

**Spec:** `docs/superpowers/specs/2026-11-08-freemapper-print-design.md` (§4 mask variant and sheet, §5.3 white-out, §5.5 project file, §5.7 overprint above masks, §7 M4 and its examples). ADRs 0025 (project file), 0034 (overprint layers), 0035 (course sheets), 0038 (number placement), 0044 (base area).

## Global Constraints

- Mask coordinates are map coordinates in millimetres at map scale, y as OOM shows it (up), the same convention as `centre_map_mm` (ADR 0028 and the manual, ch. 6). The loader converts to the internal frame once.
- A mask variant holds one or more polygons; each polygon is an outline ring plus hole rings. The masked region is the outline minus the holes (even-odd). Holes of one polygon must lie inside its outline; holes may overlap each other (their union is the window); polygons of one variant must not overlap. The loader refuses anything else with file:line.
- The mask is a clip on the map: the map (all map primitives, the base area included) is drawn only where it is visible, i.e. in the frame outside the outlines plus inside the holes (PDF clip path, nonzero rule, frame counter-clockwise, outlines clockwise, holes counter-clockwise, so overlapping holes unite). The paper stays white outside. It never hides the course overprint, the sheet elements, the frame line or the footer.
- **Automatic masks** (user decision 2026-11-10): for window orienteering the windows are always circles around the control circles, with an adjustable radius (one default for the mask, optionally per control); the generator builds them from the course. For corridor orienteering no rule for the course of the corridor exists: it is drawn individually per map and course, so the user gives the polyline; only the width is adjustable. There is no automatic corridor.
- A course has zero or one mask. An assignment names a course (by name) and optionally a mask id; a sheet without a mask prints as before, byte for byte.
- White-out objects from a `.ppen` become mask variants named `whiteout-<n>` ("white-out is read but waits for M4", ADR 0033): the reader already yields `Special::WhiteOut` with its rings and a course filter. They apply to the courses of their filter; an explicit `mask` in an assignment wins over a white-out.
- Exact scale and the credit line are untouched. All M1 to M3 example PDFs stay byte-identical (`cmp`); masks add output only where an assignment names one.
- Hostile input is bounded (ADR 0019): at most 64 mask variants, 256 polygons per variant, 4096 points per ring and 100 000 points per project; a ring has at least 3 distinct points and finite coordinates.
- Program texts in DE and EN through Fluent, passed through unslop and humanizer; German uses „…“; „Bundesland“ for German states. Every significant decision gets an ADR; every user-visible change both changelogs; new terms the glossary.
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass after every task, on three OSes. Query crates.io only with the User-Agent `freemapper-print-dev`; never put an e-mail address in a header or URL.

## Review Focus

1. **A mask that hides what the runner needs.** The user expects the course overprint, numbers and the description box always visible, and `check` to warn when a marked route, crossing point or forbidden route (upper purple) or a control lies where the mask removes the map. Pinned in Task 3: `check_warns_for_overprint_in_masked_area`, `check_warns_for_control_in_masked_area`.
2. **Holes outside the outline, overlapping polygons.** A hand-written mask with a hole outside its outline or two overlapping polygons must not silently print wrong. Overlapping holes are allowed and unite. Pinned in Task 1: `hole_outside_outline_refused`, `overlapping_polygons_refused`, and in Task 2: `overlapping_holes_unite`.
3. **Ring orientation and self-intersection.** A ring written clockwise or counter-clockwise must print the same; a self-intersecting ring is refused with file:line. Pinned in Task 1: `ring_orientation_does_not_matter`, `self_intersecting_ring_refused`.
4. **A course whose mask id no longer exists**, or a mask that no course uses. The user expects `check` to name both and the other courses to export. Pinned in Task 1: `unknown_mask_in_assignment_refused`, `unused_mask_is_noted`.
5. **The mask and the base area, the page edge.** The base area is hidden outside the windows too, nothing paints outside the frame, and a window at the map edge prints correctly. Pinned in Task 2: `mask_hides_the_base_area_outside_windows`, `window_at_the_frame_edge_is_clipped`.

### Task 4: Generators and the CLI

**Files:**
- Create: `crates/freemapper-print/src/mask_build.rs` (circle windows, corridor polygon)
- Modify: `crates/freemapper-print-cli/src/main.rs` (`masks window`, `masks corridor`), ftl files, `crates/freemapper-print/src/project.rs` (`append_mask`)

**Interfaces:**
- Produces:
  - `mask_build::windows(course, event, controls: &[ControlSel], radius_mm: f64, per_control: &BTreeMap<String, f64>) -> Result<Mask, BuildError>`: for window orienteering. One circular hole (a polygon of at least 48 vertices, vertex count by radius) around each selected control circle, centred on the control. The radius is the radius around the control centre in map millimetres at the print scale of the course... decide and document: the radius is given in print millimetres on the sheet (like a gap), so that "a window of 12 mm" looks the same at every print scale; the builder converts using the layout's print scale. The outline is a rectangle covering the map extent plus a margin. Overlapping circles are allowed (they unite). Selection: all controls of the course (default), or a list or range of control codes.
  - `mask_build::corridor(path: &[[f64; 2]], width_mm: f64, extent) -> Result<MaskPolygon, BuildError>`: the corridor along a polyline given by the user, as a hole in a rectangle outline, with mitre joins limited to twice the width; a self-intersecting result is refused with a hint. The width is in print millimetres as above.
  - CLI: `freemapper-print masks window <PROJECT> --course <NAME> [--controls <CODE,CODE|FROM-TO>] [--radius <MM>] [--radius-for <CODE=MM>]… [--id <ID>] [--assign]` and `masks corridor <PROJECT> --points "x,y;x,y;…" [--width <MM>] --id <ID> [--assign --course <NAME>]` (points in the project's mask coordinates, y up). Both append a `[[masks]]` table (and an assignment with `--assign`) as text, reload and validate, restore the old content on failure, refuse a duplicate id (exit 2) and write through `freemapper-fs` (ADR 0041). Defaults: radius 15 mm, corridor width 10 mm (print mm; check them against the manual's examples and state the reason in the ADR).
  - There is no automatic corridor and the manual says so.
