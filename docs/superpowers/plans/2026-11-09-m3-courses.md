# M3 Courses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Print one sheet per course. Courses come from Purple Pen (`.ppen`) or IOF XML 3.0. Each sheet carries
the ISSprOM/ISOM course overprint, a control description box (only for `.ppen`), and control numbers placed from
the course file, with per-layout and per-sheet corrections. `check` scores the numbers and proposes positions.

**Architecture:** A new `course` module holds the reader-neutral course model and its two readers. The readers
convert into OOM map coordinates (µm, y down) and check that the course fits the map. An `overprint` module turns
one course into purple shapes in page millimetres, in two layers (lower and upper purple, IOF Rev. 4). The PDF
writer paints the lower layer below the map's full-strength black, brown and blue and the upper layer above the
map, both with Multiply blending. A standalone `placement` module scores number positions. It does not depend on
the rest of the crate, so freemapper-courseplan can take it over. Print rules move into an embedded rule profile
in freemapper-courseplan's format.

**Tech Stack:** Rust 2024, quick-xml (already a dependency) for both readers, pdf-writer 0.15 for ExtGState
blending, and the existing renderer, sheet and export modules. No new crates are expected.

**Spec:** `docs/superpowers/specs/2026-11-08-freemapper-print-design.md`, §5.3, §5.4, §5.5, §5.7, §5.9 and §7.
ADRs 0010, 0015, 0018, 0019, 0023–0030. Partner format: freemapper-courseplan ADR 0025 (rule profiles) and its
`NumberPlacement` (`direction` in degrees, 0 = east, counter-clockwise; `gap_mm` in print mm).

## Global Constraints

- Rust edition 2024, pure-Rust core, `unsafe_code = "forbid"`, toolchain pinned (ADR 0007). Dependencies must be
  at least two weeks old (ADR 0006).
- Domain logic lives in `crates/freemapper-print`; the CLI is in `crates/freemapper-print-cli` (ADR 0001).
- English identifiers and comments. Glossary first: every new domain term gets its row in `docs/glossary.md`
  with its code.
- Every user-visible program text goes through Fluent, in `i18n/en` and `i18n/de`, and passes the unslop and
  humanizer skills. German uses correct umlauts and „…“ quotes.
- Exact scale: 1 mm at print scale is 1 PDF mm. Course symbols scale with the symbol factor of ADR 0018, the
  same way map symbols do.
- IOF Rev. 4 purple is CMYK 35/85/0/0 (spec §5.9). Lower purple (start, controls, legs, forbidden lines) lies
  below black, brown and blue 100 %. Upper purple (numbers, map exchange, forbidden areas, marked routes) lies
  above the map.
- The course file is read again on every `check` and `export` (live link). freemapper-print never writes to it.
  Assignments are keyed by course name, corrections by control code. Anything that disappeared is reported and
  kept.
- Print scale and print area in a `.ppen` are ignored for printing (the layout decides). `init` offers them as
  defaults.
- A course that does not match the map is an error, never a silent shift.
- Control number positions use courseplan's form: `direction` in degrees (0 = east, counter-clockwise) and
  `gap_mm` in print mm. The gap is the shortest distance between the outer edge of the circle line
  (r_outer = d/2 + line width/2) and the number's box, with the box centred on the direction ray (agreed with
  freemapper-courseplan, 2026-11-09). Inverse: gap = distance(circle centre, box) − r_outer.
- Hostile input is bounded the way ADR 0019 bounds maps, with the limits named in Task 2. Readers refuse
  external entities and DTDs.
- Every output keeps the credit line (ADR 0029) and names freemapper-print in the PDF metadata.
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass after
  every task.
- Commits use Conventional Commits with a scope and end with the session trailers. Every significant decision
  gets an ADR in the same branch, and every user-visible change gets an entry in both changelogs.

## Review Focus

1. **A course file whose y axis or origin does not match the map** (IOF XML from Purple Pen, Condes or OCAD with
   y up, or a `.ppen` made for another map). The user expects a clear error naming the file and the reason,
   never a sheet with the course in the wrong place. Pinned in Task 3: `y_up_detected`,
   `course_outside_map_is_error` and `georef_mismatch_is_error`.
2. **A course file that changed since the project was written** (a course renamed, a control deleted or
   recoded). The user expects `check` to name what is missing and keep the corrections, and the remaining
   courses to export. Pinned in Task 5: `renamed_course_reported_and_kept` and
   `missing_control_correction_reported`.
3. **Course names that are not file names**, such as `D/H 12`, `Bahn 1: lang`, umlauts in NFD, or two names that
   differ only in case. The user expects one PDF per course with a readable, unique file name. Pinned in
   Task 7: `course_file_names_are_safe_and_unique`.
4. **A number that ends up outside the frame, under the title block or on another circle** after a layout
   correction or a print scale change. The user expects `check` to report the conflict and propose a free
   position, never to move it silently. Pinned in Task 10: `check_reports_number_outside_frame` and
   `proposal_is_conflict_free`.
5. **A `.ppen` from a newer Purple Pen** with elements or symbol ids this reader does not know. The user expects
   the courses to print, with a note naming what was left out, and no failure. Pinned in Task 4:
   `unknown_elements_noted_not_fatal`.

### Task 3: Fitting a course to the map

**Files:**
- Create: `src/course/fit.rs`
- Modify: `docs/adr/` (new ADR "Course coordinates and the map")

**Interfaces:**
- Consumes: `CourseEvent` (Task 2), `MapDocument` with `georef` and `parts`.
- Produces:
  - `pub fn fit(event: CourseEvent, map: &MapDocument) -> Result<FittedEvent, FitError>`.
  - `FittedEvent` has the same shape as `CourseEvent`, but every point is `MapCoord` (µm, y down, as `.omap`).
  - `pub enum FitError`, with variants `OutsideMap { inside: usize, total: usize }`,
    `GeorefMismatch { metres: f64 }`, `Ambiguous`.
  - `pub enum FitNote { YUpDetected, GeorefChecked, GeorefSkipped(reason) }`.

**Rules:**
1. Convert both candidates: (x, −y) and (x, y), multiplied by 1000.
2. A candidate fits when every control lies inside the map's drawn bounding box, expanded by 10 mm.
3. If only one candidate fits, use it.
4. If both fit, prefer y up, because Purple Pen, Condes and OCAD write y up, and note `YUpDetected`.
5. If neither fits, return `OutsideMap`.
6. When the map has `crs_spec` and `ref_projected`, and the file has lat/lng (IOF XML `Position`), project the
   lat/lng to the map's CRS and compare with the chosen map position. Use transverse Mercator for UTM, with the
   CRS given as `EPSG:258NN`, `EPSG:326NN` or `+proj=utm +zone=NN`. Include grivation and scale. A difference
   over 20 m on any control is `GeorefMismatch`. For any other CRS, note `GeorefSkipped`.

- [ ] **Step 1: Failing tests.**
  - `y_up_detected`
  - `y_down_kept`
  - `course_outside_map_is_error`
  - `georef_mismatch_is_error`: a control moved by 50 m.
  - `georef_checked_on_luebeck`: a hand-made IOF XML on `tests/fixtures/maps/luebeck.omap` (EPSG:25832) whose
    lat/lng was computed from map positions with an independent tool (record the tool in the fixture README).
  - `utm_forward_matches_reference_points`: three published EPSG test points, accurate to 1 mm.
- [ ] **Step 2: Implement and verify.** Implement TM (Krüger series to n⁴ is enough) and run the tests.
- [ ] **Step 3: ADR and commit.** Write the ADR: y-axis detection, the 10 mm margin, the 20 m tolerance, and why a
  mismatch is an error. Commit `feat(course): fit course coordinates to the map`.

### Task 6: Course overprint

**Files:**
- Create: `src/overprint/mod.rs`, `src/overprint/symbols.rs`
- Modify: `src/render/page.rs`, `src/render/pdf.rs`, `docs/adr/` (new ADR "Overprint layers and blending")

**Interfaces:**
- Produces:
  - `RenderedPage.overprint: Overprint`.
  - `pub struct Overprint { lower: Vec<Shape>, upper: Vec<Shape>, below_priority: Option<i32>, colour: DirectColour }`.
    `below_priority` is the priority before whose first primitive the lower layer is painted. It is `None` when
    no full-strength black, brown or blue exists; the lower layer is then painted after all map primitives.
  - `pub fn overprint(course: &Course, event: &FittedEvent, numbers: &[(String, Pt)], to_page: impl Fn(MapCoord) -> Pt, sizes: &CourseSymbolSizes, symbol_factor: f64) -> Overprint`.
    Numbers come resolved from Task 10. In this task, pass each number at its course-file position, or due east
    with a 1 mm gap when the file has none.
  - `pub fn full_strength_priority(colours: &[RenderColour]) -> Option<i32>`. It matches by CMYK: black is
    0/0/0/1; brown has m ≥ 0.5, y ≥ 0.75, c ≤ 0.3 and k ≤ 0.2; blue has c ≥ 0.9, m ≤ 0.1, y ≤ 0.1 and k = 0. It
    returns the highest priority number among the matches.
- Drawing rules:
  - Sizes come from `CourseSymbolSizes` × symbol factor.
  - The start triangle points to the first control.
  - A leg runs from circle edge to circle edge through its bends, minus its gaps. A leg shorter than the two
    radii is not drawn.
  - Circles are drawn minus their circle gaps.
  - A score course has no legs.
  - The finish is a double circle.
  - Specials, by layer:
    - lower: out-of-bounds boundary, forbidden route crosses;
    - upper: out-of-bounds hatch, dangerous areas, marked routes, numbers, map exchange;
    - lower: crossing point, first aid, water.
  - `Text` specials use Arimo.
  - `WhiteOut` is not drawn in M3.
- PDF: one ExtGState with `/BM /Multiply` is used for both overprint layers.

### Task 10: Number placement

**Files:**
- Create: `src/placement/mod.rs`, `src/numbers.rs`
- Modify: `src/sheet/course_sheet.rs`, `src/export.rs` (check report), `docs/adr/` (new ADR "Number positions
  and the placement module")

**Interfaces:**
- `placement` (no `crate::` imports; a test reads `placement/mod.rs` and asserts there is no `crate::`):
  - `pub struct Rect { min: (f64, f64), max: (f64, f64) }`.
  - `pub enum ObstacleShape { Rect(Rect), Circle { centre, radius }, Segment { a, b, half_width }, Polygon(Vec<(f64, f64)>) }`.
  - `pub struct Obstacle { shape: ObstacleShape, weight: f64, hard: bool, label: String }`.
  - `pub struct Placement { direction: f64, gap_mm: f64 }`.
  - `pub fn number_box(centre, circle_outer_r, size: (f64, f64), p: Placement) -> Rect`. Per the Global
    Constraints, the box is centred on the direction ray at the distance where its shortest distance to the
    circle's outer edge is `gap_mm` (closed form: corner case and edge case, as courseplan's note of
    2026-11-09 in the ledger).
  - `pub fn score(box_: Rect, bounds: Rect, obstacles: &[Obstacle]) -> Score`, where
    `Score { hard: Vec<String>, cost: f64 }`. Hard conflicts are an intersection with a hard obstacle and leaving
    `bounds`. The cost is the sum over soft obstacles of weight × overlap area in mm².
  - `pub fn best(centre, circle_outer_r, size, bounds, obstacles, current: Placement) -> (Placement, Score)`.
    It searches 24 directions × gaps `[0.3, 0.8, 1.5]` mm. Placement rules (decided by the user,
    2026-11-09, shared with freemapper-courseplan):
    1. Control area first: the number box covers no point or line symbol (hard conflict); area symbols
       cost little.
    2. Preferred direction "behind": the continuation of the incoming leg past the control (direction from the
       previous circle to this one; for the first control, from the start triangle).
    3. If the box at "behind" (at the chosen gap) comes within half a line width of the outgoing leg, the
       preferred direction is the bisector of the larger sector between incoming and outgoing leg.
    4. If the preferred place is blocked, the free place with the smallest angular distance to the preferred
       direction wins: the cost adds the angular distance to the preferred direction. Score courses and
       stops without legs keep `current` as preferred.
    Obstacles need the symbol class of each map primitive: `Primitive` gains `class: SymbolClass { Point,
    Line, Area, Text }`, set by the renderer (no change to drawing).
- `numbers`:
  - `pub fn resolve(course, event, project, layout_id) -> Vec<ResolvedNumber>`, applying levels 1–4 of spec §5.7.
  - `ResolvedNumber { control, placement, level: Level, … }`.
  - `pub fn obstacles(page: &RenderedPage, course_shapes, elements: &[PlacedElement], weights: &PlacementWeights) -> Vec<Obstacle>`:
    - hard obstacles are the course's own circles, legs and other numbers, plus the sheet elements;
    - soft obstacles are map primitive bounding boxes, weighted by colour class through
      `full_strength_priority`-style CMYK classes.
  - Level 1 runs `best` for numbers the file has no position for.
  - `check` scores every number. For each hard conflict it adds a `NumberConflict { course, control, conflicts, proposal: Placement }`
    note.
